# iOS app (`ios/`)

See ios/README.md. The root CLAUDE.md keeps the colour rule and the iOS test commands.

- SwiftUI, iOS 17+, built with Xcode 27. `ios/project.yml` (XcodeGen) is the source; the `.xcodeproj` is generated and git-ignored. Scripts use `/Applications/Xcode.app` if `xcode-select` points at the Command Line Tools.
- The API client is generated at build time from `ios/EventFaces/Core/API/openapi.json`, produced from `backend/openapi.json` by `ios/scripts/sync-openapi.py`; `test.sh` fails if it is stale. Generator quirks: it **skips OpenAPI 3.1 nullable fields** (`anyOf: [T, null]`), so the sync script rewrites them as optional `T`; operation ids are `<tag>_<function>` (unique, enforced); init arguments are alphabetical; free-form `dict[str, X | None]` responses don't generate (give app-facing endpoints a pydantic response model); `format: date` fields arrive as `"YYYY-MM-DD"` strings.
- Secrets: access token in memory only; refresh token + device id in the Keychain (`AfterFirstUnlockThisDeviceOnly`, never synced); device key in the Secure Enclave (simulator: Keychain software key). Refreshes are single-flight (`SessionManager` actor): presenting a rotated token twice is treated as theft by the server.
- Networking: no cookies, no URL cache, ATS without exceptions in Release (Debug: local networking only, enforced by `ConfigurationTests`). Never log tokens, codes, emails, query strings or image data.
- Deep links are parsed strictly against `APP_LINK_HOST` (`DeepLink.parse`); new link kinds need tamper tests in `DeepLinkTests`.
- Every UI screen gets `performAccessibilityAudit` in a UI test (one helper: `EventFacesUITests/UITestSupport.auditScreen`), and audit issues are fixed, never filtered. The helper re-audits elements overlapped by system bars, the keyboard, or the edge of their innermost scroll view (iPad form sheets) after scrolling; an element must pass where it is fully visible. A contrast failure stands unless the element's rendered pixels measure ≥ 4.5:1 (IOS-025; `ContrastMeasureTests` guards the measurement). Tap targets: use `.buttonStyle(.tapTarget)` for text/icon buttons (a `.frame` outside a Button doesn't grow the tappable area); `assertTapTarget` checks 44 × 44 pt. Container `.accessibilityIdentifier`s replace their children's: put identifiers on scroll views or leaf controls only. Sheets/full-screen flows with our own header use `.hardScrollEdges()`. Lessons from Phase 1: use our own components rather than `Form` (system materials failed contrast and Dynamic Type), opaque token-coloured bars (nothing is read through glass), scroll + `fixedSize(vertical:)` for text, readable disabled states (token pair, not opacity).
- Every UI string goes through `Localizable.xcstrings` with a German translation (`ios/scripts/check-strings.py`). German uses informal "du".
- Third-party embeds (event videos: YouTube/Vimeo/Instagram/Drive, `VideosSection.swift`) render in a `WKWebView` configured with `.nonPersistent()` `WKWebsiteDataStore`, so no cookies or cache from the embedded page survive past the sheet — the same "never persist more than necessary" stance as the rest of the app. Don't switch it to the default (persistent) data store.
