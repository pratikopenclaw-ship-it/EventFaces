# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

EventFaces: attendees find event photos via selfie face search. Built in phases (see README "Status"); after each phase run tests, summarize, and stop for the user's go-ahead. Ask before adding paid services or major dependencies. GDPR applies (face embeddings are biometric data).

## Commands

Everything runs in Docker; host Python (3.9) is not used.

```bash
docker compose up -d --build                         # full stack (dev)
docker compose -f docker-compose.prod.yml --env-file .env.prod up -d --build   # production (see README)
docker compose exec api pytest -q                    # backend tests (test DB eventfaces_test, Redis DB 15, bucket eventfaces-test)
docker compose exec api pytest tests/test_auth.py::test_login_rate_limited
docker compose exec api alembic revision -m "msg"    # new migration (hand-write ops; files are NNNN_slug.py)
docker compose exec api python -m app.cli create-superadmin --email x@example.com
docker compose exec api python -m app.cli reindex-faces   # after changing FACE_ENGINE
docker compose exec api python -m app.cli export-openapi  # after any API change (iOS client source)
cd frontend && npm run lint && npx next typegen && npx tsc --noEmit && npm run build
scripts/security-scan.sh                             # all scanners; must stay 18/18 PASS (see SECURITY_QA_REPORT.md)
docker compose -f docker-compose.yml -f docker-compose.e2e.yml up -d api web && (cd frontend && npx playwright test)   # e2e; `docker compose up -d api` to switch back
scripts/backup_restore_drill.sh                      # pg_dump/pg_restore drill
scripts/release.sh vX.Y.Z                            # tag a release (main, clean, CI green); deploy on the server: scripts/deploy.sh vX.Y.Z (auto-rollback), scripts/rollback.sh
scripts/release_check.sh http://localhost:3000       # post-deploy smoke check (dev fails legal/docs checks by design)
ios/scripts/bootstrap.sh                             # iOS: colours from design/tokens.json, API schema copy, Xcode project (XcodeGen)
ios/scripts/test.sh                                  # iOS: derived-file checks + unit/integration/UI tests on iPhone + iPad (needs the e2e API)
```

E2E runs the real app via `backend/tests/e2e_server.py` (test DB, fake Drive, captured mail, `/__e2e/*` control endpoints; refuses to start unless `ENVIRONMENT=test`). New accounts created through the UI must use `example.com` (email_validator rejects `.test`). Load test: `docker-compose.load.yml` + `loadtest/eventfaces.js` (k6).

Mailpit (dev email) UI: http://localhost:8025 — also has a JSON API at `/api/v1/messages` for grabbing verify/reset links.

## Architecture

- Browser → Next.js (:3000). `next.config.ts` rewrites `/api/*` → FastAPI, so auth cookies are first-party. Frontend is mostly client components calling `src/lib/api.ts` (adds `X-CSRF-Token`, retries once after `/api/auth/refresh` on 401).
- FastAPI (`backend/app`): `api/routes/*` (thin) → `services/*` (logic) → `models/*` (SQLAlchemy 2, **sync** sessions shared with Celery). `core/` holds config (pydantic-settings, env only), security, rate limiting, email, storage.
- Celery worker + beat (`app/workers/celery_app.py`, tasks in `app/workers/tasks.py`). Tasks are thin wrappers over `services/photo_pipeline.py`: `drive.sync` → `drive.import_photo` → `photos.index` (routed to the `index` queue). `index_photo` is the shared indexing step (guest uploads reuse it in Phase 4).
- Faces: `services/faces.py` (`detect_faces`) lazily loads InsightFace buffalo_l once per process from `/models` (baked into the image). The same image serves the API and the worker because the API embeds selfies in-process, so they never touch Redis or storage. The ML deps + model are in their own Docker layer (`requirements-ml.txt`); edit `requirements.txt` for everything else.
- `photos.status` is visibility (only `published` may ever be searchable); `photos.index_status` is pipeline progress. `faces.event_id` is denormalized for event-filtered vector search.
- Images: `services/imaging.py` sniffs magic bytes and re-encodes everything to metadata-free JPEG. Storage keys are `events/<event>/photos/<photo>/<variant>.jpg`; images reach browsers only via API streaming endpoints that check the photo belongs to the path's event.
- Storage is S3-API only (boto3). Local dev uses SeaweedFS (MinIO images are no longer published) — don't reintroduce MinIO.

## Security invariants (tests enforce these; keep them true)

- **Every event-scoped route** must depend on `MemberEvent` or `ManagedEvent` from `app/api/deps.py`. Authorization logic lives only in `app/services/membership.py`. Non-members get 403 (also for unknown event IDs, to prevent probing).
- `services/search.search_faces` takes `event_id` keyword-only and filters both `faces.event_id` and `photos.event_id`, plus `photos.status == published`. `test_selfie_never_returns_photos_from_another_event` must keep passing.
- Photo visibility for non-organizers is decided only by `services/photo_access.viewable_photos` (published + unexpired grant or own upload + same event). Thumbnails, previews and downloads all go through it.
- Never return raw storage or Drive URLs. Images stream through the API, and downloads use `services/downloads` tokens bound to user + event + photos and re-checked on redemption.
- Selfies and query embeddings are never persisted: the search endpoint reads the raw body (never `UploadFile`/multipart, which spools to disk), and `test_selfie_is_never_persisted` blocks tempfile use during a search.
- Guest uploads: the only storage URL a browser ever gets is the presigned PUT (`storage.presigned_put`, signs size + type). Never make `pending_review` photos visible: `viewable_photos` and `search_faces` both require `published`.
- Anything that takes a photo out of circulation must use `photo_pipeline.retire_photo` (deletes faces, grants, files) under a row lock. `index_photo` re-checks the row after detection so it never writes embeddings for a retired photo.
- Invites: `invites.accept` requires the logged-in email to equal the invited email and must never re-approve a revoked member.
- Retention (`services/retention.py`, hourly beat) deletes an event's faces/grants at `access_expires_at`; `index_photo` refuses to index events whose retention has run. Keep both in sync if you add new biometric or derived tables: add them to `retention.expire_event`, `account.delete_account` and consent withdrawal.
- Removal requesters must never be shown matched photos or counts (stranger could fish for someone else's photos).
- Camera searches require a capture token (`services/capture_tokens.py`, GETDEL single-use, bound to user+event) and a 3-shot `application/x-selfie-set` body (front,left,right). Selfie upload needs `ALLOW_SELFIE_FILE_UPLOAD` AND `event.allow_selfie_file_upload`.
- `match_feedback` values come from the user's grant (never the client). Anything that must forget a user or an event's face data must call `feedback.anonymize_feedback` (retention, consent withdrawal and account deletion already do).
- Pose conventions (server = InsightFace): yaw > 0 = person turned to THEIR left; pitch < 0 = looking down. `frontend/src/lib/face-guidance.ts` flips MediaPipe's pitch/roll to match (calibrated in the browser on identical frames). Re-check if either library is upgraded.
- MediaPipe phones home to `odml.pa.googleapis.com`; keep CSP `connect-src` strict and the fetch guard in `guided-capture.tsx`.
- Security guards were mutation-tested: when you change one, check that a test fails if the guard is removed.
- `rate_limit.client_ip` only trusts `X-Forwarded-For` per `TRUSTED_PROXY_HOPS`; don't read that header elsewhere.
- Opaque tokens (refresh/verify/reset/invite) are stored only as SHA-256 hashes via `services/tokens.py`.
- Sessions: access JWTs carry `sid` and are valid only while their session has a live refresh token (`tokens.session_is_live`); logout/reset/deletion end sessions immediately; replaying a rotated refresh token outside `REFRESH_REUSE_GRACE_SECONDS` revokes the session.
- Overflow searches (`services/search_queue.py`) keep selfies in process memory only: never put them (or embeddings) on Celery/Redis/disk. Redis holds only the job status. The worker re-checks user, consent and membership before matching, and shares `core/face_slots` with synchronous searches. `tests/test_search_queue.py` enforces this.
- Face-model work (seconds, serialized per process) must never run while the request holds a DB connection or row lock: commit/rollback first (search route, removal submit). `tests/test_pool_starvation.py` enforces it; the k6 load test found the pool exhaustion this prevents.
- Every authorization change must keep `tests/test_authz_matrix.py` green; a new endpoint fails its completeness check until added to `OPS`. Rate-limited endpoints are listed in `tests/test_endpoint_contracts.py::RATE_LIMITED`.
- Client timestamps are `UtcDatetime` (timezone required, normalized to UTC). Images are checked against `IMAGE_MAX_PIXELS`/`SELFIE_MAX_PIXELS` from the header before decoding. `Settings` refuses insecure production config; keep new secrets in that validator.
- The face model is behind `services/face_engine.FaceEngine` (`FACE_ENGINE`); only `services/faces.py` calls it. Faces store `model` and `search_faces` filters on the current model; never compare embeddings across models (`tests/test_face_engine.py`, mutation-checked).
- Password hashing (Argon2, ~64 MiB each) goes through `security.hash_password`/`verify_password`, which cap concurrency per process; callers must commit/rollback first so no pooled connection is held while hashing (`tests/test_password_hashing.py`). Pool exhaustion and every capacity limit answer 503 + Retry-After, never 500.
- Mobile app (bearer) auth, `api/deps.get_current_user`: a request with `Authorization` is judged on the header alone (cookies ignored); access JWTs carry `aud` (`web` = cookie only, `mobile` = header only). CSRF is skipped only for requests with no auth cookie that carry `Authorization` or hit `/api/mobile/auth/*` (`api/csrf.cookieless_app_request`); those endpoints never read or set cookies. `tests/test_authz_matrix.py` runs every cell over cookie **and** bearer and they must agree: add new ops for both (`transports=`).
- App sessions are devices (`models/device.py`, `services/mobile_auth.py`): the refresh-token family in `auth_tokens` plus a Secure Enclave public key. `/api/mobile/auth/refresh` needs a fresh (±60 s), never-reused ECDSA signature and a token from that device's own session; the web `/api/auth/refresh` refuses device-session tokens. Anything that ends sessions (logout, reset, deletion) must also revoke devices (`revoke_user_devices`, `account.delete_account`). Sign-in codes are HMACs in Redis, single-use, die after `MOBILE_CODE_MAX_ATTEMPTS`, and count toward the join-style lockout; purposes (`signin`/`reauth`) never mix.
- App Attest (`services/app_attest.py`) is **report-only**: results go on the device row and into logs as reason codes and must never block a request until an explicit enforce decision. Production pins Apple's root (fingerprint in `tests/test_app_attest.py`); the CBOR decoder is hand-written (definite lengths only, depth/size caps) and every parser error must become `AttestError` (the fuzz test fails otherwise). Challenges are single-use per device (GETDEL); one attested key belongs to one device; assertions are bound to the signed refresh message and the counter must increase. Guards were mutation-checked.
- App requests (bearer or `/api/mobile/auth/*`) below `IOS_MIN_SUPPORTED_VERSION` get 426 (`api/app_version.py`); keep `/api/app/config` exempt.
- Push (`services/push.py`): payloads come only from `push.payload` (loc-keys + `kind`/`event_id`/`search_id`, asserted against `PAYLOAD_KEYS`): never names, photos, counts or email addresses. Send after commit (background task), never while holding a connection.
- `backend/openapi.json` is the iOS client's source: after any API change run `python -m app.cli export-openapi` (`tests/test_openapi_contract.py` fails otherwise). Raw-body endpoints document their bodies via `openapi_extra` (`api/selfie.SEARCH_OPENAPI`).
- Legal documents (Terms, Organizer Terms with the Art. 28 DPA, Privacy Notice with its cookie section, Impressum) are server-owned in `services/legal.py` (German binding + English), served by `GET /api/legal/{document}` to web and app; the operator identity comes from `LEGAL_*` settings (production refuses to start without them). Changing any word needs a `VERSIONS` bump (`tests/test_legal.py` pins hashes). Every account creation requires `accept_terms` (StrictBool) and records a `legal_acceptances` row; `get_verified_user` answers 403 + `X-Required-Action: accept-terms` without the current Terms, `get_managed_event` 403 + `accept-organizer-terms` without the Organizer Terms (super admins exempt). CurrentUser-only routes (account, deletion, consent withdrawal, devices, logout) never require acceptance. A new cookie must be added to the privacy notice's cookie section (`legal.DOCUMENTED_COOKIES`, test-enforced).
- Consent text is server-owned (`services/consent_text.py`, en + de, chosen by Accept-Language) and returned with `/api/me/face-consent`; web and app render it. Changing any word requires bumping `FACE_CONSENT_VERSION` (`tests/test_consent_text.py` pins a hash per version).
- `POST /api/join/by-code` (code only, the app's typed-code path) shares `_admit` with the slug join; its lockout is global per user and per IP because one endpoint covers every event.
- Theme: no inline script and no CSP change. The root layout renders `<html data-theme>` from the `ef_theme` cookie (only system|light|dark, via `lib/theme.parseThemePref`; System = no attribute + CSS media query). `users.theme` is an enum; login/refresh/`PATCH /api/me/preferences` set the cookie. Per-event `accent_color` lands in a style attribute: keep it `#rrggbb`-only (schema validator + DB CHECK + `accentStyle`). `tests/test_theme.py`, `e2e/theme.spec.ts`.
- Error reports (GlitchTip, Sentry protocol): backend `core/monitoring.scrub` is the only filter (no bodies, cookies, auth headers, query strings, local vars, emails, tokens; user = opaque id); the SDK is also configured never to collect bodies/PII/locals. Web has **no SDK**: browsers post a few string fields to the same-origin `/monitoring` route, which redacts (`lib/error-report.ts`) and builds the event itself for the server-only DSN (never forwards client envelopes; same-origin check + size + rate limits); server errors via `src/instrumentation.ts`. CSP stays `connect-src 'self'`. Tests: `test_monitoring.py`, `error-report.test.ts`, `e2e/monitoring.spec.ts` (fake GlitchTip in `e2e_server.py`); all guards mutation-checked. Production requires `SENTRY_DSN` (https, or http only to the internal `glitchtip` host).
- Billing (`services/billing`): `plans.py` is the only price list (pricing page, checkout, limits). Only a verified provider confirmation (`provider.parse_confirmation`: HMAC over `t.body`, ±300 s, right amount + currency) marks an order paid, via `orders.apply_confirmation`, which is idempotent (`webhook_events` + pending-only fulfilment). The fake provider's pay endpoint accepts only `TEST_CARDS` and never stores or echoes the number (the global 422 handler in `main.py` drops `input`). Webhooks are CSRF-exempt only without auth cookies (`api/csrf.py`). Fulfilment creates the event via `events.new_event`, adds the buyer as organizer, promotes attendee → organizer; the Organizer Terms gate still applies. Plan limits (`limits.py`, event row locked) apply in `join._admit`, `invites.accept`, guest uploads and Drive sync; NULL limits = admin-made event. Orders survive account deletion unlinked (`orders.forget_user` ends subscriptions). Production refuses the fake provider unless `ALLOW_TEST_PAYMENTS=true`. Guards mutation-checked in `tests/test_billing.py`. iOS has no purchase UI (App Store rules).
- `CI` (`.github/workflows/ci.yml`): actions pinned by SHA, `permissions: contents: read`, no secrets. `@visual` is excluded there (macOS baselines) and stays a local gate.
- Indexes created in migrations must also be declared on the models (`tests/test_migrations.py` compares schema and metadata).

## iOS app (`ios/`, see ios/README.md)

- SwiftUI, iOS 17+, built with Xcode 27. `ios/project.yml` (XcodeGen) is the source; the `.xcodeproj` is generated and git-ignored. Scripts use `/Applications/Xcode.app` if `xcode-select` points at the Command Line Tools.
- The API client is generated at build time from `ios/EventFaces/Core/API/openapi.json`, produced from `backend/openapi.json` by `ios/scripts/sync-openapi.py`; `test.sh` fails if it is stale. Generator quirks: it **skips OpenAPI 3.1 nullable fields** (`anyOf: [T, null]`), so the sync script rewrites them as optional `T`; operation ids are `<tag>_<function>` (unique, enforced); init arguments are alphabetical; free-form `dict[str, X | None]` responses don't generate (give app-facing endpoints a pydantic response model); `format: date` fields arrive as `"YYYY-MM-DD"` strings.
- Colours: `design/tokens.json` is the single source for web (`globals.css`, checked by `theme-tokens.test.ts`) and iOS (`ios/scripts/gen-colors.py` → Asset Catalog, checked by `ConfigurationTests`). Never hard-code colours in either.
- Secrets: access token in memory only; refresh token + device id in the Keychain (`AfterFirstUnlockThisDeviceOnly`, never synced); device key in the Secure Enclave (simulator: Keychain software key). Refreshes are single-flight (`SessionManager` actor): presenting a rotated token twice is treated as theft by the server.
- Networking: no cookies, no URL cache, ATS without exceptions in Release (Debug: local networking only, enforced by `ConfigurationTests`). Never log tokens, codes, emails, query strings or image data.
- Deep links are parsed strictly against `APP_LINK_HOST` (`DeepLink.parse`); new link kinds need tamper tests in `DeepLinkTests`.
- Every UI screen gets `performAccessibilityAudit` in a UI test (one helper: `EventFacesUITests/UITestSupport.auditScreen`), and audit issues are fixed, never filtered. The helper re-audits elements overlapped by system bars, the keyboard, or the edge of their innermost scroll view (iPad form sheets) after scrolling; an element must pass where it is fully visible. A contrast failure stands unless the element's rendered pixels measure ≥ 4.5:1 (IOS-025; `ContrastMeasureTests` guards the measurement). Tap targets: use `.buttonStyle(.tapTarget)` for text/icon buttons (a `.frame` outside a Button doesn't grow the tappable area); `assertTapTarget` checks 44 × 44 pt. Container `.accessibilityIdentifier`s replace their children's: put identifiers on scroll views or leaf controls only. Sheets/full-screen flows with our own header use `.hardScrollEdges()`. Lessons from Phase 1: use our own components rather than `Form` (system materials failed contrast and Dynamic Type), opaque token-coloured bars (nothing is read through glass), scroll + `fixedSize(vertical:)` for text, readable disabled states (token pair, not opacity).
- Every UI string goes through `Localizable.xcstrings` with a German translation (`ios/scripts/check-strings.py`). German uses informal "du".

## Conventions

- Next.js 16: middleware is `src/proxy.ts`; `params`/`searchParams` are Promises (server `page.tsx` awaits them and passes plain props to a client component). Check `frontend/node_modules/next/dist/docs/` before using unfamiliar Next APIs.
- Tests use fixtures in `backend/tests/conftest.py` (`make_user`, `login_as`, `make_event`, `add_member`, `mailer`); tables are truncated, Redis flushed and test-bucket objects deleted after each test. Celery runs eagerly (`task_eager_propagates`), so a task's `self.retry` surfaces as `celery.exceptions.Retry`; test exhausted retries by monkeypatching `app.workers.tasks.MAX_RETRIES`.
- Upload tests do real presigned PUTs against SeaweedFS (conftest signs for the internal `S3_ENDPOINT_URL`). When writing binary files from `docker compose exec` for manual testing, don't pipe stdout: InsightFace prints load logs to stdout and corrupts the file. Write to a path and `docker compose cp` it out.
- Selfie tests use `tests/helpers.selfie_set(i)` / `search_as(client, event, i)` (640×480 frames straightened from the group photo). conftest relaxes three selfie limits for these upscaled frames (front yaw 15, side yaw 3, det 0.75); tests of the gate itself set thresholds explicitly.
- Search tests (`tests/test_search.py`) split InsightFace's group photo into left/right halves (3 different people each) and synthesize selfies with `tests/helpers.selfie_of(i)`.
- Colours are tokens in `globals.css` (`@theme`, light) with one dark set repeated for the media query, `[data-theme="dark"]` and `.theme-dark` islands (gallery, viewer: always dark). Use token classes (`text-ink/70`, `bg-accent text-on-accent`), never raw hex or `text-white` on token backgrounds (camera views use `bg-black`). `src/lib/theme-tokens.test.ts` checks every pair at 4.5:1 in both themes; keep `SURFACES` in `lib/accent.ts` and `THEME_COLOR` in `lib/theme.ts` in sync. Visual baselines: `npx playwright test e2e/visual.spec.ts --update-snapshots` after intended visual changes (darwin baselines).
- Frontend camera: `selfie-capture.tsx` uses a generation counter so superseded `getUserMedia` calls stop their own stream (React dev double-mount would otherwise leave the camera on).
- Drive in tests: `drive.set_drive_client(FakeDrive(...))` (`tests/helpers.py`); the real client is tested with googleapiclient's `HttpMockSequence`. Face tests use InsightFace's bundled `t1.jpg` (6 faces) via `tests/helpers.group_photo_bytes()`.
